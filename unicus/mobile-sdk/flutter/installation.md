# Installation

## Package contents

Tekbees delivers the Flutter SDK as a ZIP package. Hosted repositories (pub,
Maven, CocoaPods, Swift Package Manager) are coming soon.

| Path | Contents |
| --- | --- |
| `sdk/unicus_sdk_flutter/` | The plugin your app depends on: the Dart API (source), the compiled Android and iOS bridges, the native Unicus SDK binaries and the biometric engine. |
| `sdk/unicus_sdk_flutter/android/repo/` | Local Maven repository with the Android binaries. The plugin registers it for your build; you do not declare it. |
| `sdk/unicus_sdk_flutter/ios/` | `UnicusSDK.xcframework`, `<Unicus verification engine>.xcframework` (production and development builds), the privacy manifest and the Podfile helper `unicus_facetec_development.rb`. |
| `example/` | Runnable example app. `example/lib/quick_start.dart` is the minimum integration in one file. |
| `QUICKSTART.md`, `ERRORS.md`, `TECHNICAL_INTEGRATION.md` | Offline copies of the quick start, the error codes and a technical reference. |

The package contains binaries only: there is no plugin or native source to
edit, and nothing to change in `MainActivity` or `AppDelegate`.

## 1. Add the dependency

Copy `sdk/unicus_sdk_flutter` into your repository, for example
`vendor/unicus_sdk_flutter`, and add it to `pubspec.yaml`:

{% code overflow="wrap" %}
```yaml
dependencies:
  unicus_sdk_flutter:
    path: vendor/unicus_sdk_flutter
```
{% endcode %}

{% code overflow="wrap" %}
```bash
flutter pub get
```
{% endcode %}

Commit the folder with your app (or store it in your internal artifact
repository) so every build uses the same version. To update, replace the
folder with the one of the new package and run `flutter pub get` again.

## 2. Android

### Gradle versions

| Item | Minimum for the SDK | Notes |
| --- | --- | --- |
| `minSdk` | 21 | `flutter.minSdkVersion` of current Flutter versions already meets it. |
| `compileSdk` | 34 | `flutter.compileSdkVersion` of current Flutter versions already meets it. |
| Android Gradle Plugin | 8.x or 9.x | With AGP 9, built-in Kotlin on or off. **Flutter 3.47 requires AGP 8.11.1 or newer.** |
| Kotlin Gradle Plugin | 2.0 | The SDK targets Kotlin API/language 2.0. **Flutter 3.47 requires 2.2.20 or newer.** |
| JDK | 17 | Required by AGP 8. |

Your Flutter version sets the real minimums: use the versions that
`flutter create` generates for it. For Flutter 3.47, in
`android/settings.gradle.kts`:

{% code overflow="wrap" %}
```kotlin
plugins {
    id("dev.flutter.flutter-plugin-loader") version "1.0.0"
    id("com.android.application") version "8.11.1" apply false
    id("org.jetbrains.kotlin.android") version "2.2.20" apply false
}
```
{% endcode %}

AGP 8.11.1 needs Gradle 8.13 or newer
(`android/gradle/wrapper/gradle-wrapper.properties`).

In `android/app/build.gradle.kts`, the values generated by Flutter are fine:

{% code overflow="wrap" %}
```kotlin
android {
    compileSdk = flutter.compileSdkVersion // 34 or higher
    defaultConfig {
        minSdk = flutter.minSdkVersion // 21 or higher
    }
}
```
{% endcode %}

### Permissions

The plugin merges `CAMERA` and `INTERNET` into your manifest. Location is
optional and **not** merged. If you want Unicus to register where the
verification started, declare it in `android/app/src/main/AndroidManifest.xml`
(and report it in the *Data safety* section of Play Console):

{% code overflow="wrap" %}
```xml
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```
{% endcode %}

Without these permissions, or when the user denies them, the verification
continues without location.

### R8 / ProGuard

Nothing to add. The keep rules of the plugin, the native SDK and the biometric
engine ship inside their libraries and are applied automatically to your
release build.

### WebView

Flows with UI steps (consent, form, signature, OTP) need an up-to-date
*Android System WebView* (Chromium 90 or newer). Otherwise `start` throws
`webview_unavailable` before showing anything. The plugin does not depend on
`webview_flutter`, so there is no version conflict with your app.

## 3. iOS

### Deployment target and CocoaPods

The iOS part is integrated with CocoaPods. In `ios/Podfile`:

{% code overflow="wrap" %}
```ruby
platform :ios, '15.0'
```
{% endcode %}

Then install the pods (Flutter also does it on `flutter run` / `flutter build ios`):

{% code overflow="wrap" %}
```bash
cd ios
pod install
```
{% endcode %}

{% hint style="info" %}
Swift Package Manager is not supported in this release. The plugin has no
`Package.swift`, so Flutter integrates it with CocoaPods even when SPM is
enabled (it prints a warning). Keep `ios/Podfile`. To silence the warning,
disable SPM for your app in `pubspec.yaml`:

```yaml
flutter:
  config:
    enable-swift-package-manager: false
```
{% endhint %}

### Info.plist

In `ios/Runner/Info.plist`:

{% code overflow="wrap" %}
```xml
<key>NSCameraUsageDescription</key>
<string>We use the camera to verify your identity.</string>
<!-- Optional: location as transaction metadata; without it the verification continues. -->
<key>NSLocationWhenInUseUsageDescription</key>
<string>We register where the verification starts.</string>
```
{% endcode %}

If your app declares `WKAppBoundDomains`, add the flow screens domain of your
environment (Tekbees provides it). Otherwise `start` throws
`webview_domain_not_allowed` before showing anything. See
[Compatibility and security](../compatibility-and-security.md).

### Debug builds on a physical iPhone

The production build of the biometric engine does not run in Debug builds on
a device (debugger attached). The package ships its development build and a
Podfile helper that swaps it in with a build phase. Add the helper to
`ios/Podfile`:

{% code overflow="wrap" %}
```ruby
require File.expand_path('.symlinks/plugins/unicus_sdk_flutter/ios/unicus_facetec_development.rb', __dir__)

post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)
  end
  unicus_install_facetec_development_swap(File.join(__dir__, 'Runner.xcodeproj'))
end
```
{% endcode %}

If your Podfile already has a `post_install` block, add only the
`unicus_install_facetec_development_swap` line to it. Then run `pod install`
(or `flutter run`).

* The phase only acts on **signed Debug builds for a device** (`iphoneos`).
  Simulator, Profile, Release and `--no-codesign` builds keep the production
  framework, so your App Store build is not affected.
* The phase is idempotent: running `pod install` again updates it.
* If your app target is not called `Runner`, pass its name as the second
  argument: `unicus_install_facetec_development_swap(path, 'MyApp')`.

## 4. Check the installation

Run the example of the package, or your app, on a physical device:

{% code overflow="wrap" %}
```bash
flutter devices
flutter run -d <DEVICE_ID> --dart-define=UNICUS_API_KEY=<CUSTOMER_TOKEN>
```
{% endcode %}

`--dart-define` values are compiled into the build: use it for local tests
only and load the Customer Token from your own configuration in your app.
