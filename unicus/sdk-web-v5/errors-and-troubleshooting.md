## Screens shown to the user

The Unicus web app shows a titled error screen, in the user's language, with a
code when one applies. The customer page receives the same case through
`OnUnicus:error` (error screens; `OnUnicus:exit` follows when the user closes
them) or `OnUnicus:finished` (result screens). Error screens that allow it show
a **Retry** button; in the iframe they also show **Close**.

| User sees | Code | Cause | What to do |
| --- | --- | --- | --- |
| The link is not valid | — | The URL had no transaction or hand-off token. | Open the flow from the button or from a link generated by Unicus. |
| The session expired or was already used | `2051` (or `401`) | Transaction expired, already completed, or reopened from an old link. | Create a new transaction (close and click the button again). |
| The link expired or was already used | `2051` | One-time hand-off link opened twice or after it expired. | Generate a new QR/SMS/WhatsApp from the computer. |
| We couldn't continue right now. Please try again | `2054` | Unicus could not process the request at that moment. The link and the transaction are still valid. | The user presses **Retry** on the same screen. No new transaction, QR or message is needed. |
| This transaction has no verification flow configured | `2002` | No flow for this company and transaction type. Usually caught earlier: the button itself shows "Verification not configured". | Assign a flow in the portal. |
| This verification has a configuration we do not recognise | — | The flow contains something this version of the web app cannot run. | Review the flow in the portal; contact support. |
| This step could not continue | `2052` | The server refused a step (for example out of order, or not in the flow); the reason is shown. No Retry button. | Usually the flow changed while the transaction was open: start a new transaction. |
| Too many attempts | `429` | Too many requests from the same device in a short time. | Wait a moment and press **Retry**. |
| Your session does not match this verification | `403` | The session belongs to another transaction. | Reopen from a fresh link. |
| We could not connect | — | No connection, or an unexpected answer from Unicus. | Press **Retry**. |
| We could not start the secure camera | `9997`, `9004` | The camera components could not be loaded or the biometric service did not answer. | Press **Retry**; check the browser and network. |
| Camera permission was denied (result screen) | `9996` | The user refused camera access. The flow ends with a failure: `OnUnicus:finished` with `9996`. | Ask the user to allow the camera in the browser settings and start again. |
| Rotate your phone to portrait to continue (camera screen) | — | The phone was rotated during the capture. | Rotate back to portrait; the capture continues. |
| We could not verify your identity (result screen) | step code | A required step failed, or the user cancelled the camera (`2041`). | Show the user a retry option; the code says why. |
| Under review | `2013` | Manual review pending. | Wait for the webhook. |

## Diagnosing integration problems

| Symptom | Check |
| --- | --- |
| The button stays grey with "Retry" | `OnUnicus:error` (and the browser console) has the cause. Most common: the Customer Token belongs to another environment, `clientid` has no number, or the API domain is blocked by CSP (`connect-src`). |
| The button says "Verification not configured" | Result code `2002`: assign a flow to the transaction type in the portal, or remove a wrong `data-flow-id`. |
| The button is neutral grey and never changes | The transaction is not being created. Confirm `customerid` and `transactiontype` are set when the element connects, and that the script loaded (`customElements.get('unicus-btn')` is defined). `button.getAttribute('state')` tells you where it is. |
| Nothing happens on click | A click during `loading` opens the flow when the transaction is ready (up to 30 seconds on a slow network). If the state is `error`, read `OnUnicus:error`. Clicks are ignored in `no_flow` and with the `disabled` attribute. Check that no overlay of your page intercepts the click. |
| The page is covered for a few seconds and the button goes back to "Retry" | The verification could not load (`OnUnicus:error`: *the verification could not be loaded*). Check CSP `frame-src`, ad or privacy blockers, and the network. |
| The iframe is blank | CSP `frame-src` must allow the Unicus web app domain. Check the browser console for a refused frame. |
| The camera never opens | The site must be served over HTTPS; the iframe needs the `camera` permission (set by the button; a parent `Permissions-Policy` header that denies `camera` overrides it). On a computer the camera is never used: the flow hands off to a phone. |
| Events never fire | Listeners must be attached to the element in the DOM (or to `document`, since events bubble). With React, attach in `useEffect` through a `ref`. Event names are case sensitive: `OnUnicus:finished`. |
| The verification closes by itself, without `finished` or `exit` | Your page removed or re-created the `<unicus-btn>` element (route change, conditional rendering, re-keyed list). Keep it mounted while the verification is open. |
| `OnUnicus:loaded` fires several times | Expected after a change of `customerid`, `clientid`, `transactiontype` or `data-flow-id`, and on the first click after `finished` / `exit`. Always keep the latest `tid`. |
| `finished` arrives with `success: false` and `resultCode: 2013` | Not an error: the transaction is under manual review. |
| The desktop mirror stops updating | The computer also checks the transaction with Unicus every few seconds and shows the result when Unicus has it. The result is in Unicus either way and reaches your webhook. |
| The company logo or colours do not appear | The branding is configured in the portal for the same environment as the Customer Token. Colours must be hex (`#rrggbb`). |

## Diagnostic log

The verification screens do not show technical details to the user. When an
issue needs a closer look, Tekbees can enable a diagnostic log in the sandbox
environment: a panel on the verification screens with a timestamped log of the
last steps of the flow. Ask for it through [Support](support.md).

## What to send to support

* `tid` of the transaction.
* Version of the button: `customElements.get('unicus-btn').version`.
* Browser and device (user agent).
* The `OnUnicus:error` or `OnUnicus:finished` payload.
* The diagnostic log, when Tekbees enabled it for you.
* Date and time with time zone.
